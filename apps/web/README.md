# Chunking Lab web app

Next.js 15 (App Router) + Supabase Auth. Pages:

| Route | What it does |
|-------|--------------|
| `/` Overview | Corpus counters, chunk layouts, embedding sets, four separate resource panels, ingestion throughput |
| `/search` Retrieval Lab | Keyword / vector / hybrid search; context policy, token budget and expansion; ranked units with fusion ranks; budget bar |
| `/explorer` | A filing's canonical text with any chunk layout's boundaries drawn over it; layout comparison; answer-span containment |
| `/benchmarks` | Parameter curves (does size help?), quality-vs-cost Pareto frontier, results table |
| `/method` | What is measured and what each cost means |

**Access.** Every route and API needs a Supabase session; the data functions additionally check the allow-list
(`rag.app_users`). See `docs/DEPLOY.md`.

**Data layer.** The browser never talks to the database. Server code calls the read-only `public.lab_*` functions
as the signed-in user. `LAB_FIXTURE=1` (local development only) reads a local Postgres through the same functions.
